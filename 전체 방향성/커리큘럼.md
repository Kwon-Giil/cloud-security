# Cloud Security / DevSecOps / Security QA Curriculum

## 1. 학습 목표

약 8~9개월 동안 기존 QA 실무 경험을 기반으로 다음 영역의 역량을 단계적 확장.

* Linux / Network / Web Fundamentals
* Web Security
* Cloud / Infrastructure as Code
* Container / Kubernetes Security
* DevSecOps / CI/CD Security
* Security QA / Security Automation

최종적으로 각 기술을 독립적으로 경험하는 것이 아니라, **웹 애플리케이션 → 클라우드 인프라 → 컨테이너 → CI/CD → 보안 검증 → Security QA**를 하나의 흐름으로 연결한 통합 프로젝트 구축.

---

# 2. 학습 구조

```text
Long-term Goal
    ↓
Monthly Goal
    ↓
Weekly Goal
    ↓
Lesson
    ↓
Concept / Practice
    ↓
Accumulated Assessment
    ↓
TIL
```

### 기본 원칙

* 월간 목표는 해당 기간에 확보할 핵심 역량을 정의.
* 주간 목표는 월간 목표를 달성하기 위한 세부 역량을 정의.
* 일일 Lesson은 주간 목표를 달성하기 위한 하나의 완결된 학습 흐름으로 구성.
* 개별 Concept를 독립적인 Lesson으로 과도하게 분리하지 않음.
* 관련된 개념은 하나의 시스템, 현상, 문제 또는 데이터 흐름을 중심으로 연결.
* Day 단위의 세부 계획은 학습자의 실제 이해도와 실습 결과에 따라 조정.

# 4. 평가 원칙

평가는 개별 Concept 또는 Lesson 직후에 기계적으로 실행하지 않음.

일정 범위의 학습이 누적된 후 이전 내용을 회상하고 연결할 수 있는 시점에 평가 진행.

평가 방법은 주제에 따라 유연하게 사용.

* 질의응답
* 자신의 말로 설명
* 사고 실험
* 실제 실습
* 문제 해결
* 누적 종합 문제

평가의 목적은 단순 암기가 아니라 **개념을 연결하고 실제 상황에 적용할 수 있는지 확인하는 것**.

# 5. 진도 조정

전체 Curriculum은 고정된 시간표가 아니라 상위 학습 Roadmap으로 사용.

다음 상황에서는 일일/주간 계획을 조정 가능.

* 선수지식 부족
* 예상보다 높은 난이도
* 실습 환경 문제
* 추가 학습 필요
* 이미 알고 있는 내용
* 예상보다 빠르거나 느린 학습 속도

중요한 선수지식을 생략하면서 진도를 맞추지 않음.

반대로 하나의 개념을 충분히 이해했음에도 불필요하게 반복하지 않음.

**학습 일정 자체보다 실제 이해와 수행 능력을 우선한다.**

# 6. Lesson Guidelines

하나의 Lesson은 다음 구조를 기본으로 함.

```text
상위 목표 확인
→ 관련 개념 학습
→ 이해 확인
→ 시뮬레이션 / 실습
→ 결과 해석
→ 누적 평가
→ 다음 학습
```

다만 모든 Lesson에 모든 단계를 기계적으로 적용하지 않음.

하나의 Lesson은 개별 Concept가 아니라 **하나의 현상, 시스템 흐름, 문제 또는 수행 목표가 완결되는 범위**를 기준으로 구성.

예:

```text
Browser
→ HTTP Request
→ Burp Proxy
→ Request Manipulation
→ Server Processing
→ Response
```

이 전체를 하나의 Lesson으로 구성할 수 있다.

반대로 하나의 중요한 주제가 깊은 분석을 요구한다면 하나의 주제를 여러 Lesson에 걸쳐 학습할 수 있다.

# 7. Learning Record

TIL은 개별 개념의 사전식 설명보다 하나의 학습 결과를 기록하는 단위로 작성한다.

기본적으로 다음 내용을 기록한다.

* 학습 목표
* 학습 내용
* 직접 수행한 실습
* 예상과 실제 결과
* 문제 및 필요한 경우 Troubleshooting
* 검증 결과
* 배운 점
* 부족한 점
* 다음 학습

모든 학습 세션에 Troubleshooting을 억지로 추가하지 않음.

실제 오류를 원인 분석하고 해결한 경우에만 별도로 기록.

또한 모든 AI 대화를 그대로 기록하지 않음.

학습에 영향을 준 질문, 문제 해결 과정, 중요한 피드백만 필요한 범위에서 기록.
