## 2. 학습 내용
### Web Communication

웹 서비스는 기본적으로 클라이언트와 서버가 네트워크를 통해 데이터를 주고받는 구조로 동작함.

Client
  ↓
Request
  ↓
Server / Application
  ↓
Response
  ↓
Client

HTTP는 클라이언트와 서버가 데이터를 주고받기 위한 통신 규칙이며, HTTPS는 여기에 TLS를 적용하여 통신을 보호하는 방식
 - TLS: http 환경에서 데이터를 암호화하여 무결성을 지키면서 인증할 수 있는 프로토콜 방식

HTTP/HTTPS를 학습하면서 웹 브라우저에서 서버로 요청이 전달되고, 서버가 결과를 응답하는 기본적인 흐름 이해

### Server & Infrastructure

웹 서비스를 제공하기 위해서는 애플리케이션을 실행할 서버와 네트워크, 저장공간 등의 인프라 필요

서버와 인프라는 웹 서비스가 실제로 동작하기 위한 기반이며, 이후 보안 학습에서도 이러한 구성요소와 데이터 흐름을 이해하는 것이 중요하다는 점 확인

### Why Cloud?

클라우드는 컴퓨팅, 네트워크, 저장공간 등의 인프라 자원을 필요에 따라 사용할 수 있도록 제공하는 방식

클라우드를 사용하는 이유로 다음과 같은 개념을 학습

- 필요한 자원을 유연하게 사용할 수 있음
- 서비스 규모에 따라 자원을 확장하거나 축소할 수 있음
- 물리적인 인프라를 직접 구축하고 관리하는 부담을 줄일 수 있음
- 서비스를 운영하는 방식 자체를 유연하게 구성할 수 있음

## 3. 이해한 내용

웹 보안을 이해하기 위해서는 먼저 정상적인 웹 서비스의 동작 흐름을 이해해야 한다는 점을 확인

사용자
  ↓
브라우저
  ↓
HTTP Request
  ↓
Server / Application
  ↓
처리
  ↓
HTTP Response
  ↓
사용자

이후 보안 학습에서는 이 흐름에서 어떤 데이터가 전달되고, 어디에서 검증이 이루어지며, 어떤 부분이 공격 또는 조작의 대상이 될 수 있는지를 확인하게 된다.

또한 클라우드는 웹 서비스가 동작하는 인프라를 구성하는 하나의 방식이며, 웹 애플리케이션 자체와 클라우드 인프라는 서로 다른 계층의 개념이라는 점을 이해했다.
