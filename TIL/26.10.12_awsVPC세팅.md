# Terraform AWS VPC 네트워크 구성

**Date:** 2026-10-12  
**Category:** Cloud / AWS / Terraform / Networking / Security

## 1. 학습 목표

Terraform을 이용하여 AWS VPC 네트워크 구성을 코드로 정의하고, 변수와 출력값을 별도 파일로 분리하여 관리하는 방법을 익힌다.

또한 `terraform plan`, `terraform apply`, `terraform destroy`를 실행하면서 인프라 구성 검토, 생성, 정리까지의 흐름을 경험.

---

## 2. 학습 내용

### 2.1 Terraform 파일 구성

기존 Terraform 리소스 정의에 변수 선언과 출력값을 추가하여 구성 정리.

| 파일 | 역할 |
|---|---|
| `main.tf` | VPC, 서브넷, 라우팅 테이블, 보안 그룹 등 AWS 리소스 정의 |
| `variables.tf` | 프로젝트 이름, VPC CIDR, 서브넷 CIDR 등 설정값 정의 |
| `outputs.tf` | 구성한 리소스에서 필요한 결과값을 출력하도록 정의 |

이를 통해 리소스 구성과 설정값을 분리하고, 프로젝트 이름이나 네트워크 대역을 변수로 관리하는 기본 구조 구성.

### 2.2 AWS VPC 네트워크 구성

Terraform 코드에서 다음 네트워크 구조 정의.

```text
VPC
├── Internet Gateway
│
├── Public Subnets (2개 AZ)
│   ├── Public Route Table
│   ├── Elastic IP
│   └── NAT Gateway
│
├── Private Subnets (2개 AZ)
│   └── Private Route Table
│       └── NAT Gateway로 외부 통신
│
└── Security Groups
    ├── Web Security Group
    │   └── HTTP / SSH
    └── Private DB / App Security Group
        └── Web Security Group으로부터의 접근 허용
```

퍼블릭 서브넷은 Internet Gateway를 통한 외부 통신을 담당하도록 구성하고, 프라이빗 서브넷은 NAT Gateway를 통해 외부로 나가는 트래픽을 전달하도록 정의.

또한 두 개의 가용 영역을 활용하도록 서브넷을 구성하고, 웹 서버용 보안 그룹과 프라이빗 DB·애플리케이션용 보안 그룹 분리.

이번에는 네트워크 리소스의 생성 구조를 Terraform 코드로 정의하는 데 초점을 두었음.

## 3. Hands-on

| 실습 | 수행 내용 | 확인 결과 |
|---|---|---|
| Terraform 구성 작성 | VPC, IGW, 서브넷, NAT Gateway, 라우팅 테이블 및 보안 그룹 정의 | AWS 네트워크 구성을 코드로 표현 |

## 4. Troubleshooting

### 4.1 저장된 Plan의 유효성 문제

terraform apply 실행 과정에서 다음 오류 발생.

```text
Error: Saved plan is stale

The given plan file can no longer be applied because the state was changed by another operation after the plan was created.
```

저장된 Plan을 생성한 이후 Terraform State가 변경되어 기존 계획을 그대로 적용할 수 없는 상태였음.

변경된 상태를 반영하기 위해 다음 명령으로 Plan을 다시 생성

```bash
terraform plan -out=tfplan
```

이후, 아래의 커맨드로 apply까지 정상적으로 진행되는 것까지 확인 완료

```bash
terraform apply tfplan
```
