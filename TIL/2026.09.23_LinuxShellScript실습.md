# Linux Bash Shell Scripting

**Date:** 2026-09-23
**Category:** Linux / Bash / Automation

## 1. 학습 목표

Linux 기본 명령어를 복습하고, Bash Shell Script를 이용하여 여러 작업을 하나의 스크립트로 실행하는 기본적인 자동화 과정을 이해.

또한 Shell Script를 작성하고 실행 권한을 부여한 뒤 실제 결과를 확인하는 과정을 경험.

---

## 2. 학습 내용

### 2.1 Linux 기본 명령어 복습

이전 학습에서 확인한 Linux 기본 명령어의 용도와 사용 방법을 간단히 복습

명령어 자체를 모두 암기하기보다 필요한 작업에 맞는 명령어를 선택하고, 여러 명령어를 조합하여 작업을 수행할 수 있다는 점을 다시 확인함.

### 2.2 Bash Shell Script

Bash는 Linux 환경에서 명령어를 실행하고 여러 작업을 하나의 스크립트로 작성하여 반복 작업을 자동화할 수 있는 Shell임

오늘은 직접 Shell Script를 작성하고 실행하면서 **Linux 명령어를 개별적으로 사용하는 것과 여러 명령어를 스크립트로 묶어 실행하는 것의 차이**를 확인함.

### 2.3 백업 Shell Script 작성

실습용 디렉터리를 생성한 뒤 백업 작업을 수행하는 Shell Script를 작성함.

작성한 스크립트에 실행 권한을 부여하고 직접 실행하여, 테스트용 로그 파일이 정상적으로 생성되는지 확인함.

전체 흐름은 다음과 같음.

```text
디렉터리 생성
  ↓
백업 Shell Script 작성
  ↓
실행 권한 부여
  ↓
가짜 로그 파일 생성
  ↓
스크립트 실행
  ↓
결과 파일 생성 여부 확인
```

## 4. Troubleshooting

### 4.1 Nano 편집기 사용 방법 혼선

Shell Script를 작성하는 과정에서 Nano 편집기의 기본적인 편집 및 종료 방법을 몰라 작업에 시간이 소요됨.

편집기에서 파일을 수정하고 저장한 뒤 종료하는 기본적인 사용 흐름을 확인함.

### 4.2 파일 경로 확인 과정에서 혼선

실습 파일과 디렉터리의 위치를 찾는 과정에서 경로를 혼동하여 여러 차례 확인함.

현재 작업 디렉터리와 실제 파일 위치를 확인하면서 필요한 경로로 이동하는 과정을 익혔음.

### 4.3 `chmod +x` 실행 후 예상과 다른 권한 표시

Shell Script에 실행 권한을 부여하기 위해 `chmod +x`를 실행한 후 파일 권한이 다음과 같이 표시되는 것을 확인함.

```text
-rwxrwxrwx
```

처음에는 실행 권한을 추가한 결과 모든 사용자에게 권한이 열린 것처럼 보여 원인을 확인함.

확인 결과, WSL에서 Windows 파일시스템(NTFS) 내부의 파일을 사용하는 경우 Linux의 권한 모델과 다르게 Windows 파일 권한이 Linux 권한 형태로 표시될 수 있음을 확인함.

이를 통해 **WSL에서는 작업 중인 파일이 Linux 파일시스템에 있는지, Windows 파일시스템에 있는지에 따라 파일 권한 표시 및 동작이 달라질 수 있다는 점**을 이해함.

### 4.4 비밀번호 입력 시 화면에 아무것도 표시되지 않는 현상

Linux 환경에서 비밀번호를 입력할 때 **아무 글자나 별표(`*`)가 화면에 표시되지 않는 현상**을 확인했다.

입력이 되지 않는 것으로 생각했으나, 터미널에서는 보안을 위해 비밀번호 입력 내용을 화면에 표시하지 않는 것이 일반적인 동작임을 확인함.

비밀번호를 입력한 후 `Enter`를 눌러 정상적으로 입력되는 것을 확인함.

## 5. Assessment

Linux 명령어를 단독으로 사용하는 것과 Shell Script를 통해 여러 작업을 묶어서 실행하는 것의 차이를 설명할 수 있는지 확인함.

또한 작성한 Script에 실행 권한을 부여하고 직접 실행하여 결과 파일이 정상적으로 생성되는지 확인함.

## 6. 오늘 배운 점

오늘은 Linux 기본 명령어를 복습한 뒤 Bash Shell Script를 직접 작성하고 실행함.

이를 통해 Linux 명령어를 하나씩 실행하는 것에서 나아가 **반복적으로 수행하는 작업을 Shell Script로 묶어 자동화할 수 있다는 기본적인 개념**을 이해함.

또한 Script 작성 과정에서 편집기 사용, 파일 경로 확인, 실행 권한 설정 등 Linux 환경에서 작업할 때 필요한 기본적인 흐름을 직접 경험함.

특히 WSL에서 Windows 파일시스템의 파일을 다룰 때 Linux 환경과 다른 권한 표시가 나타날 수 있다는 점과, 비밀번호 입력 시 화면에 입력 내용이 표시되지 않는 터미널의 동작을 직접 확인함.

## 7. Key Takeaway

오늘은 Linux 명령어 복습과 함께 Bash Shell Script를 직접 작성하여 실행하면서 **Linux CLI에서 수행하는 작업을 스크립트로 묶어 자동화할 수 있다는 점**을 경험함.

아직 Bash의 다양한 문법이나 고급 스크립팅까지 학습한 단계는 아니지만, Linux 명령어 → Shell Script → 실행 → 결과 확인으로 이어지는 기본적인 자동화 흐름을 직접 경험한 것에 의미를 두었음.

또한 Linux 환경에서 문제가 발생했을 때 명령어 자체뿐만 아니라 **작업 중인 파일시스템과 실행 환경의 특성까지 확인해야 한다는 점**을 경험함.
