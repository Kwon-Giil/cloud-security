# Cloud 네트워크 및 접근 제어 모사 실습

**Date:** 2026-10-05
**Category:** Cloud / Network / Security / Docker

## 1. 학습 목표

Cloud 환경에서 VPC, Public / Private Network, IAM, NACL, 방화벽 등의 기본 개념을 이해하고, 이를 Docker 환경에서 단순화하여 직접 모사.

또한 Proxy, Application, Database를 분리된 Network에 배치하고, 네트워크 접근 제어를 적용하여 특정 접근은 허용하고 다른 접근은 차단되는 구조를 직접 확인.

---

## 2. 학습 내용

### 2.1 VPC와 Public / Private Network

Cloud 환경에서는 하나의 네트워크 안에서도 외부에 노출되는 영역과 내부에서만 사용하는 영역 분리 가능.

실습에서는 Docker Network를 이용하여 이를 단순화하고 다음과 같은 구조 구성.

```text
Public Network
      ↓
    Proxy
      ↓
Private Network
      ↓
 Application
      ↓
 Database
```

Docker Compose에서는 `public-net`과 `private-net`을 별도로 생성.

Proxy는 두 Network에 모두 연결하여 외부 요청을 받아 Private Network의 Application으로 전달하도록 구성했다. 반면 Application과 Database는 Private Network에만 연결.

또한 `private-net`에 `internal: true`를 설정하여 외부와 직접 연결되지 않는 내부 Network를 구성.

### 2.2 Proxy를 이용한 접근 구조

Nginx를 Proxy로 사용하여 외부 요청을 내부 Application으로 전달하는 구조를 구성.

Proxy는 Host의 `8080` 포트를 통해 외부에서 접근할 수 있도록 설정하고, 내부적으로 `secret-app:5678`로 요청을 전달하도록 구성.
이를 통해 다음과 같은 구조를 확인.

```text
외부 요청
   ↓
Nginx Proxy
   ↓
Private Network
   ↓
Secret Application
```

### 2.3 IAM과 접근 권한

Cloud 환경에서는 네트워크가 연결되어 있더라도 사용자나 서비스의 권한에 따라 리소스에 대한 접근을 제한할 수 있다.

오늘은 IAM의 기본 개념을 학습하고, 접근 권한에 따라 특정 접근은 허용하고 다른 접근은 차단하는 구조 확인.

이를 통해 **네트워크 연결과 리소스 접근 권한은 별개의 문제**라는 점 이해.

### 2.4 NACL을 이용한 접근 제어 모사

NACL의 패킷 필터링 개념을 학습하고 이를 Nginx의 접근 제어 규칙을 이용하여 단순화.

Nginx 설정에서는 특정 IP를 차단하는 규칙을 먼저 적용하고, 실습에서는 `deny all`을 사용하여 로컬에서 들어오는 접근까지 강제 차단.

```text
외부 요청
   ↓
IP / 접근 조건 확인
   ↓
차단 조건이면 거부
   ↓
조건을 통과한 요청만
Private Application으로 전달
```

이번 실습은 실제 NACL을 사용하는 것이 아니라 **NACL의 접근 제어 원리를 로컬 환경에서 모사한 것**.

### 2.5 이중 방화벽 구조

하나의 접근 제어만 사용하는 것이 아니라 여러 보안 계층을 적용하는 구조를 모사했다.

```text
접근 요청
   ↓
1차 접근 제어
   ↓
2차 접근 제어
   ↓
Application
```

실습에서는 접근 제어 규칙을 추가하여 로컬에서 들어오는 요청까지 차단하고, 여러 단계의 보안 설정을 통과해야 내부 서비스에 접근할 수 있는 구조 확인.

이를 통해 Cloud 환경에서는 하나의 방화벽이나 접근 제어 설정에만 의존하지 않고 **여러 보안 계층을 조합하여 방어할 수 있다는 개념**을 경험.

### 2.6 Secret과 환경변수

Database 인증정보는 Docker Compose 파일에 직접 기록하지 않고 `.env` 파일의 환경변수를 통해 전달.

Compose에서는 다음과 같이 환경변수를 받아 Database Container에 전달하도록 구성.

```yaml
environment:
  MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
```

이를 통해 인증정보를 Compose 설정에서 직접 노출하지 않고 환경변수 형태로 전달하는 구조를 확인했다.

또한 `.env` 파일을 `.gitignore`에 등록하여 Git 저장소에 포함되지 않도록 구성했다.

## 3. Hands-on

### 3.1 Public / Private Network 구성

Docker Compose를 이용하여 다음 두 개의 Network를생성.

```text
docker-vpc-lab_public-net
docker-vpc-lab_private-net
```

Proxy는 Public / Private Network에 모두 연결하고, Application과 Database는 Private Network에만 연결했다.

이를 통해 외부 요청을 받는 Proxy와 내부 서비스의 Network 분리.

### 3.2 Proxy 및 Application 구성

Proxy는 Nginx를 사용하고 Host의 `8080` 포트를 통해 요청을 받을 수 있도록 구성.

Application은 `hashicorp/http-echo` Container를 사용하여 Private Network 내부에서 응답하도록 구성.

### 3.3 Database 추가

Private Network에 MariaDB Container를 추가하여 Database 역할의 내부 서비스를 구성.

```text
Private Network
 ├─ Application
 └─ Database
```

Database 인증정보는 `.env`의 환경변수에서 전달하도록 구성.

### 3.4 접근 차단 테스트

Nginx 설정에서 특정 IP 차단 규칙과 `deny all`을 적용하여 접근을 제한.

```text
특정 IP
   ↓
차단

그 외 요청
   ↓
추가 접근 제어
   ↓
통과 여부 확인
```

이번 실습에서는 `deny all`을 적용하여 로컬에서 접근하는 요청도 차단되는 것을 확인하면서, 접근 제어 설정에 따라 서비스 연결 여부가 달라질 수 있음을 경험.

### 3.5 Compose 환경 재구성

다음 명령을 이용하여 전체 환경을 제거한 뒤 다시 생성.

```bash
docker compose down
docker compose up -d
```

이를 통해 Compose 파일에 정의된 Network와 Container를 다시 구성하는 과정을 확인.

## 4. Troubleshooting

### 4.1 Docker Compose `version` 속성 경고

Docker Compose를 실행할 때 다음과 같은 경고가 반복해서 표시됨.

```text
the attribute `version` is obsolete, it will be ignored
```

Compose 실행 자체는 정상적으로 진행되었으며 Network와 Container도 정상적으로 생성되었다.

따라서 이번 실습에서는 기능상의 오류가 아니라 Compose 파일의 `version` 속성에 대한 경고임을 확인.

### 4.2 Proxy 재시작 상태 확인

다음 명령으로 Proxy Service 재시작 시도.

```bash
docker-compose restart proxy
```

실행 과정에서 다음과 같이 `Restarting` 상태가 표시되는 것을 확인.

```text
Container docker-vpc-lab-proxy-1 Restarting
```

현재 확인한 로그에서는 이후 최종 상태까지 확인되지 않았으므로, Proxy 재시작이 정상적으로 완료되었는지는 추가 확인이 필요.

## 6. 오늘 배운 점

오늘은 Cloud에서 사용하는 VPC, Public / Private Network, IAM, NACL, 방화벽 등의 개념을 학습하고 이를 Docker 환경에서 단순화하여 직접 모사.

특히 Proxy를 Public Network에 노출하고 Application과 Database는 Private Network에 배치하면서 **외부에서 직접 접근할 수 있는 영역과 내부에서만 사용하는 영역을 분리하는 구조**를 경험.

또한 Nginx의 `deny` 규칙을 이용하여 특정 IP와 모든 외부 접근을 차단해보면서, 실제 Cloud 환경의 NACL이나 방화벽과 동일한 구현은 아니더라도 **접근 제어 규칙이 트래픽 흐름을 제한하는 원리**를 직접 확인.

Database 인증정보는 `.env`를 통해 전달하고 `.gitignore`로 제외하면서 Secret을 소스 코드와 분리하는 기본적인 방식도 함께 경험.

## 7. Key Takeaway

오늘은 지금까지 학습한 Docker와 Network 개념을 Cloud의 네트워크 보안 구조와 연결.

```text
VPC 개념
   ↓
Public / Private Network
   ↓
Proxy
   ↓
Application / Database
   ↓
IAM / NACL / Firewall
   ↓
접근 허용 / 차단
```

특히 실제 Cloud Provider를 사용하지 않고도 **Docker Network와 Nginx 접근 제어를 이용하여 Cloud의 네트워크 분리와 보안 접근 제어 원리를 직접 모사할 수 있었음.**

다만 이번 실습은 Cloud 서비스 자체를 구현한 것이 아니라, **Docker와 Nginx를 이용하여 VPC 및 NACL 등의 개념을 학습하기 위한 단순화된 모사 환경**이라는 점을 구분.
