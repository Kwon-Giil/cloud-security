# 클라우드 컴퓨팅 개념 및 기존 학습 내용 매핑

**Date:** 2026-10-04
**Category:** Cloud / Infrastructure

## 1. 학습 목표

클라우드 컴퓨팅의 기본 개념을 이해하고, 기존에 학습한 Linux, Network, Docker, CI/CD 기술이 Cloud 환경에서는 어떤 형태로 연결되는지 확인.

또한 Region, Availability Zone, VPC, Subnet, EC2 등의 기본적인 Cloud 인프라 구성요소가 서로 어떻게 연결되는지 이해.

아직 특정 Cloud 환경에서 실제 리소스를 생성하기보다는, 지금까지 학습한 내용을 Cloud 관점에서 다시 바라보며 이후 Cloud 학습을 위한 기본 구조를 잡는 것을 목표.

## 2. 학습 내용

### 2.1 클라우드 컴퓨팅

클라우드 컴퓨팅은 직접 서버나 인프라를 구축하고 관리하는 대신, 필요한 컴퓨팅 자원과 서비스를 Cloud 환경을 통해 사용하는 방식.

기존에는 직접 Linux 환경을 구성하고 Docker Container를 실행했다면, Cloud에서는 이러한 컴퓨팅 자원과 네트워크, 스토리지 등을 Cloud 서비스 형태로 구성됨.

오늘은 특정 Cloud 서비스를 하나씩 익히기보다 **기존에 사용했던 기술이 Cloud 환경에서는 어떤 구성요소로 연결되는지**를 중심으로 학습.

### 2.2 IaaS / PaaS / SaaS

Cloud 서비스는 사용자가 관리해야 하는 범위에 따라 IaaS, PaaS, SaaS와 같은 형태로 구분할 수 있음.

```text
IaaS
→ 서버, 스토리지, 네트워크 등 기본 인프라를 제공

PaaS
→ 애플리케이션 실행에 필요한 플랫폼 환경을 제공

SaaS
→ 완성된 소프트웨어를 서비스 형태로 제공
```

이를 통해 Cloud는 단순히 원격 서버를 사용하는 것만이 아니라, **인프라부터 애플리케이션 수준까지 다양한 형태의 서비스를 제공하는 환경**이라는 점을 이해.

### 2.3 Region / Availability Zone

Cloud 인프라는 여러 지역과 물리적인 데이터센터 단위로 구성.

* **Region**: Cloud 리소스를 배치하는 지리적인 영역
* **Availability Zone(AZ)**: 하나의 Region 안에서 서로 독립적으로 구성된 가용 영역

여러 AZ를 사용하면 하나의 영역에 문제가 발생하더라도 다른 영역을 활용할 수 있어 가용성을 높이는 구조를 만들 수 있음.

### 2.4 VPC / Subnet / EC2

Cloud에서 가상 서버와 네트워크를 구성할 때 다음과 같은 관계를 이해함.

```text
Region
 ├─ Availability Zone A
 │    ├─ Public Subnet
 │    └─ Private Subnet
 │
 └─ Availability Zone B
      ├─ Public Subnet
      └─ Private Subnet

VPC
 └─ 위 Subnet들을 포함하는 논리적인 네트워크 영역
```

VPC는 Cloud 환경에서 리소스를 배치하는 **논리적인 네트워크 영역**이며, Subnet은 VPC 내부의 네트워크를 나누는 단위.

Subnet은 특정 Availability Zone에 속하며, EC2와 같은 컴퓨팅 리소스를 특정 Subnet에 배치 가능.

**EC2**는 Cloud에서 가상 서버를 생성하고 사용하는 대표적인 컴퓨팅 서비스이다.

기존에 Linux 환경에서 직접 서버를 사용했던 것과 비교하면, EC2를 통해 Cloud에서 필요한 가상 서버 자원을 생성하고 운영할 수 있음.

### 2.5 기존 학습 내용과 Cloud 환경의 대응

지금까지 학습한 내용을 Cloud 환경과 연결하면 다음과 같이 생각할 수 있음.

| 기존에 학습한 내용                   | Cloud 환경에서 대응되는 개념                    | 역할                                |
| ---------------------------- | ------------------------------------- | --------------------------------- |
| **Linux 서버**                 | **EC2와 같은 Compute 서비스**               | Cloud에서 실행할 가상 서버 자원              |
| **IP / Port / Network**      | **VPC / Subnet / Routing / Firewall** | Cloud 환경의 네트워크 구성 및 접근 제어         |
| **SSH**                      | **EC2 원격 접속**                         | Cloud 서버에 원격으로 접속                 |
| **Docker Image**             | **Container Registry**                | Container Image를 저장하고 관리          |
| **Docker Container**         | **EC2 / Container Service**           | Container 기반 애플리케이션 실행            |
| **Docker Volume / Storage**  | **Cloud Storage / Block Storage**     | 애플리케이션 데이터 저장                     |
| **GitHub Actions / Jenkins** | **CI/CD**                             | 소스 코드 변경에 따른 자동화된 작업 실행           |
| **GHCR**                     | **Cloud Container Registry**          | Cloud 환경에서 사용할 Container Image 저장 |
| **Linux 권한 / 사용자**           | **Identity / Access Management**      | 사용자와 서비스의 접근 권한 관리                |

이를 통해 Cloud는 기존에 학습한 기술을 완전히 다른 방식으로 사용하는 것이 아니라, **기존의 서버·네트워크·스토리지·권한·Container 등의 개념을 Cloud 서비스로 구성하는 방식**으로 이해할 수 있음.

### 2.6 로컬 환경과 Cloud 환경의 구조 비교

기존에 실습한 환경의 구조는 다음과 같음.

```text
GitHub
   ↓
GitHub Actions / Jenkins
   ↓
Docker Image
   ↓
GHCR
   ↓
Docker Container
   ↓
Linux / Network
```

이를 Cloud 환경으로 확장하면 다음과 같은 구조로 연결할 수 있음.

```text
GitHub
   ↓
CI/CD
   ↓
Container Image
   ↓
Cloud Container Registry
   ↓
EC2 / Container Service
   ↓
VPC / Subnet
   ↓
Internet
```

세부적인 서비스 구성은 Cloud Provider에 따라 달라질 수 있지만, **소스 코드 → CI/CD → Container Image → Registry → 실행 환경 → Network**라는 기본적인 구조는 유지할 수 있음.

### 2.7 Cloud 학습 방향

오늘은 AWS 또는 특정 Cloud Provider의 서비스를 실제로 구축하지 않고, 먼저 Cloud 환경에서 필요한 기본 구성요소의 역할을 이해하는 데 집중.

앞으로는 다음과 같은 영역을 중심으로 Cloud 인프라를 학습.

```text
Cloud
 ↓
Region / Availability Zone
 ↓
Network
 ├─ VPC
 ├─ Subnet
 └─ Routing / Firewall
 ↓
Compute
 └─ EC2
 ↓
Storage
 ↓
Identity / Permission
 ↓
Database
 ↓
Container / CI/CD
```

## 3. Hands-on

### 3.1 기존 학습 내용 Cloud 매핑

지금까지 직접 실습한 내용을 Cloud 환경의 구성요소와 연결하여 비교.

```text
Linux
  ↓
Cloud Compute / EC2

IP / Port / Network
  ↓
VPC / Subnet / Routing / Firewall

Docker Image
  ↓
Container Registry

Docker Container
  ↓
EC2 / Container Service

GitHub Actions / Jenkins
  ↓
Cloud 기반 CI/CD

권한
  ↓
Identity / Access Management
```

실제 Cloud 리소스를 생성하지 않고도 **기존에 학습한 기술과 Cloud 구성요소의 관계를 정리하는 방식으로 실습**

### 3.2 Cloud 인프라 구성요소 관계 확인

Region, Availability Zone, VPC, Subnet, EC2의 관계를 정리하면서 Cloud 환경에서 가상 서버와 네트워크가 어떤 구조로 연결되는지 확인.

```text
Region
├─ Availability Zone A
│    ├─ Subnet
│    │    └─ EC2
│
└─ Availability Zone B
     ├─ Subnet
          └─ EC2

VPC
└─ 위 Subnet들을 포함하는 네트워크 영역
```

실제 구조에서는 VPC가 Region 범위의 네트워크 영역이고, 각 Subnet이 특정 AZ에 속하며 EC2가 해당 Subnet에 배치된다는 관계 이해.


## 6. 오늘 배운 점

오늘은 클라우드 컴퓨팅의 기본 개념과 IaaS, PaaS, SaaS의 차이를 학습하고, Region과 Availability Zone, VPC, Subnet, EC2 등의 기본적인 Cloud 인프라 구성요소가 어떻게 연결되는지 확인.

또한 지금까지 공부했던 Linux, Network, Docker, CI/CD 등의 기술이 Cloud 환경에서는 Compute, Virtual Network, Container Registry, CI/CD 등의 구성요소로 연결될 수 있다는 점을 확인.

특히 Linux 서버를 Cloud의 EC2와 연결하고, 기존 Docker Image와 Container를 Cloud의 Registry 및 Container 실행 환경과 연결해보면서 **기존에 알고 있던 기술을 기반으로 Cloud 구조를 이해할 수 있다는 점**을 경험.

## 7. Key Takeaway

오늘은 다음과 같이 Cloud의 기본 구조와 기존 학습 내용 연결

```text
Cloud
 ↓
Region / AZ
 ↓
VPC / Subnet
 ↓
EC2
```

그리고 기존 기술을:

```text
Linux
   ↓
Compute / EC2

Network
   ↓
VPC / Subnet / Routing / Firewall

Docker
   ↓
Container / Container Registry

CI/CD
   ↓
Cloud 기반 자동화
```

와 같이 연결했다.

아직 실제 Cloud 환경에서 리소스를 구축한 단계는 아니지만, **지금까지 학습한 로컬 환경의 기술들이 Cloud에서는 더 큰 인프라 구조 안에서 연결된다는 기본적인 관점**을 잡을 수 있었음.
