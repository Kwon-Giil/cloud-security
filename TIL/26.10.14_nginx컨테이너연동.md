# Terraform 코드 리팩토링 및 Nginx 컨테이너 배포 검증

**Date:** 2026-10-14  
**Category:** Cloud / AWS / Terraform / Infrastructure as Code / Networking

## 1. 학습 목표

기존에 하나의 파일(`main.tf`)에 모여 있던 Terraform 코드를 역할별로 분리하여 구조 정리.

또한 지난 실습에서 작성한 네트워크·보안 그룹 구성이 실제로 의도한 대로 동작하는지, Public·Private EC2에 Nginx 컨테이너를 배포하여 검증.

---

## 2. 학습 내용

### 2.1 Terraform 코드 리팩토링

기존에 하나의 파일에 몰려 있던 리소스 정의를 역할별로 분리.

| 파일 | 역할 |
|---|---|
| `providers.tf` | AWS 프로바이더 설정, S3/DynamoDB 원격 백엔드 정의 |
| `variables.tf` | 프로젝트 전반에서 사용하는 주요 변수 선언 및 관리 |
| `main.tf` | VPC, 서브넷, 보안 그룹, EC2 등 핵심 인프라 리소스 정의 |
| `outputs.tf` | 퍼블릭 IP 등 생성된 리소스의 주요 출력값 정의 |

Backend 설정, 변수, 리소스 정의, 출력값을 각각 다른 파일로 분리함으로써 코드 가독성을 높이고, 이후 리소스가 늘어나더라도 파일별 역할이 유지되도록 구조 정리.

### 2.2 Bastion 경유 Private EC2 접속 구성

Private EC2는 설계상 퍼블릭 IP를 갖지 않으므로, 외부에서 직접 접속할 수 없었음.

이번 실습에서는 Public EC2를 경유지로 하는 Bastion 방식으로 Private EC2에 접속하는 경로를 구성했다. Public EC2까지는 기존에 허용된 SSH 접근으로 연결하고, 그 안에서 다시 Private EC2로 접속하는 흐름으로 구성.

### 2.3 Nginx 컨테이너 배포 및 네트워크 검증

Public EC2와 Private EC2 양쪽에 Docker를 설치하고 Nginx 컨테이너를 각각 배포.

| 대상 | 검증 목적 | 방법 |
|---|---|---|
| Public EC2 | `web_sg`의 HTTP(80) 인바운드 규칙이 의도대로 동작하는지 확인 | 외부에서 Public EC2의 퍼블릭 IP로 접속하여 Nginx 기본 페이지 확인 |
| Private EC2 | NAT Gateway를 통한 외부 통신 경로가 정상 동작하는지 확인 | Bastion으로 접속한 뒤, Docker 이미지를 정상적으로 pull 받을 수 있는지 확인 |

두 가지 검증 모두 정상적으로 통과. Public EC2는 외부에서 Nginx 페이지에 접속이 확인되었고, Private EC2는 퍼블릭 IP 없이도 NAT Gateway를 통해 이미지를 pull 받아 컨테이너를 정상적으로 실행.

이를 통해 지난 실습에서 코드로만 정의했던 네트워크·보안 그룹 구성이, 실제 AWS 환경에서 의도한 대로 동작한다는 것을 확인.

## 3. Hands-on

| 실습 | 수행 내용 | 확인 결과 |
|---|---|---|
| Terraform 코드 리팩토링 | `main.tf`에 몰려 있던 코드를 `providers.tf`/`variables.tf`/`main.tf`/`outputs.tf`로 분리 | 파일별 역할 분리 완료 |
| Bastion 접속 경로 구성 | Public EC2를 경유하여 Private EC2에 접속하는 흐름 구성 | 접속 경로 구성 완료 |
| Public EC2 Nginx 배포 | Docker 설치 및 Nginx 컨테이너 실행 | 외부에서 정상 접속 확인 |
| Private EC2 Nginx 배포 | Bastion 경유 접속 후 Docker 설치 및 Nginx 컨테이너 실행 | NAT Gateway를 통한 이미지 pull 및 컨테이너 실행 확인 |

## 5. 오늘 배운 점

하나의 파일에 모여 있던 Terraform 코드를 역할별로 분리하면서, 코드 구조를 설계값(변수)·리소스 정의·출력값·백엔드 설정으로 나누어 관리하는 방식을 익혔음.

또한 Private 서브넷에 배치한 리소스에 접근할 때는 Bastion 같은 별도의 접속 경로가 필요하다는 점을, 설계뿐 아니라 실제 접속까지 진행하며 체감함.

---

## 6. Key Takeaway

오늘은 다음 흐름 진행.

```text
Terraform 코드 리팩토링 (파일 역할 분리)
              ↓
Bastion 경유 Private EC2 접속 경로 구성
              ↓
Public EC2 Nginx 배포 → 외부 접속 검증
              ↓
Private EC2 Nginx 배포 → NAT Gateway 통신 검증
```

**코드로 정의한 네트워크·보안 설계가 실제 환경에서도 의도대로 동작하는지, 컨테이너 배포를 통해 직접 검증하는 과정** 경험.
